# ETH

## 概述

BTC更像数字黄金，作为去中心化的价值存储工具；以太坊是一个去中心化的全球计算机，通过智能合约构建一个可编程的应用生态

以太坊被视作一个状态机，通过智能合约的代码更新其状态

记录的内容是交易+交易执行后的结果，而不是每一个Wei

### EVM

**Ethereum Virtual Machine**，以太坊虚拟机

是以太坊网络中执行智能合约的运行时环境，或者说是一个去中心化的全球计算机

和BTC一样，外部账户发起交易后，网络中的每个节点都会下载这笔交易，并在各自的EVM上运行它

**成本（Gas）**：EVM的运行的每一个操作码都对应一个特定的Gas消耗量，防止恶意代码或过度消耗网络资源

假如发起的ETH转账需要消耗21000Gas，设定Gas Price为50GWei，则一共需要1050000GWei，即0.00105ETH

### PoS

以太坊从Pow转向了PoS，史称`Merge`

- PoW

工作量证明，需要花费大量的电量进行算力竞争，算出无意义的数字，需要51%攻击才能成功

- PoS

权益证明机制

出块权和投票权由节点质押的代币数量决定

**质押	**用户将32ETH锁定在链上的智能合约中，充当保证金；随机抽选节点担任验证者

**验证者**

每个`solt`时间槽中，都会选出一名提议者，收集交易内存池里的未确认交易，运行EVM虚拟机计算出新的状态，广播新去区块状态

会随机抽很多验证者组成委员会进行投票、

**最终性**

当一个Epoch打包的区块超过了2/3的赞成，就是`Justified`已证明状态，绝对不可篡改或回滚



## 账户类型

从底层看，ETH支持的账户类型有两种：外部账户和合约账户

**外部账户 （EOA）**

人类用户通过密码学（ECB椭圆曲线加密）私钥控制的账户，拥有私钥即拥有账户的绝对控制权

- 发起交易

以太坊所有的状态变更、转账和合约调用，都是EOA发起并签名的交易

EOA不存在任何EVM代码

**合约账户 （CA）**

部署在以太坊区块链上的智能合约代码实体

没有私钥，完全由内部的EVM字节码逻辑控制

- 被动响应

无法主动发起交易，接收到内部调用后才能触发代码响应

**基础字段**

- Nonce

EOA：表示该账户已发送交易的数量

CA：表示该账户已创建合约的数量

- balance

该账户持有的Wei数量（1EHT=10的18次方Wei）

- codeHash

EOA：空字符串的哈希

CA：合约的EVM字节码的加密哈希

- storageRoot

EOA：为空

CA：指向保存合约持久化状态变量的`Merkle Patricia Tree`的哈希值



## 状态树

以太坊本质上是一个基于交易的状态机，需要解决一系列工程问题

**全局状态(S)：**在任意时刻t，整个网络中所有账户的最新数据集合

**状态转换：**当包含若干交易的区块被执行时，状态发生演进
$$
S_{t+1} = \Upsilon(S_t, B_{t+1})
$$
其中r代表EVM的状态转换函数，B代表区块

存储和管理必须满足以下条件：

```
密码学可校验性：唯一哈希状态根
高效的随机读写：能够在logn时间复杂度完成对任意账户查询
快速防篡改证明：无需完整状态数据即可验证
历史状态追踪与回滚：支持旧状态历史留存
```



### **数据结构**

**key生成逻辑**

在主状态树中，并不是直接使用原始的20字节以太坊地址，而是进行`Keccak-256`计算，输出32字节固定长度哈希

为了防止Dos攻击，处理后均匀离散

**Value数据结构**

value值是一个4个固定字段的数据对象，就是账户类型的四个数据

```
AccountStruct = {
    nonce:       uint64,   // EOA 的交易发送计数 / CA 的合约创建计数
    balance:     uint256,  // 账户持有的 Wei 数量
    codeHash:    bytes32,  // 合约代码字节码的 Keccak-256 哈希值
    storageRoot: bytes32   // 该账户独立存储树（Storage Trie）的根节点哈希值
}
```

### **Merkle Patricia Trie**

简称MPT树，以同时满足高效读写和轻量密码学验证

**Trie**

前缀树，能够共享公共前缀，提高查询效率

如果公共前缀很少，会造成空间浪费

**Patricia Tree**

基数树，如果一个节点是父节点唯一的子节点，这两个节点会合并在一起，可以节省存储空间

**Merkle Tree**

每个父节点的哈希值均由其所有子节点的哈希计算而来，从而再整个树的顶层生成一个唯一的状态根

**节点结构类型**

在MPT树中，结合树的结构，就有了四种节点

```
空节点
分支节点-为一个长度为17的列表，字节点的哈希和终止符
叶子节点
扩展节点-压缩合并后的节点
```

通过16进制前缀编码确定节点类型

### 区块组成

**区块头**

由基于MPT树的三种树组成

- 世界状态树

世界状态树记录了以太坊网络中所有账户的最新状态

- 交易树

记录了当前区块中打包的所有交易内容

- 回执树

记录了当前区块中所有交易执行后的结果与附带信息

**节点结构**

不同的节点会进行不同程度的裁剪

- 全节点

保留完整的历史区块数据以及最近状态的状态树

- 归档节点

保留创世以来每一个区块的Trie完整个体

- 轻节点

仅保存区块头





## 交易

交易是指由外部账户签名并且广播到网络的一条密码学指令，是触发以太坊EVM变更的唯一源头

由以下字段组成

- from：发送者的地址
- recipient：接收地址
- signature：发送者的标识符
- nonce：表示来自账户的交易数量
- value：发送者向接收者转移的ETH数量
- input data：任意数据的可选字段
- gasLimit：交易可以消耗的最大数量燃料单位
- maxPriorityFeeGas：支付给区块验证者的消费
- maxFeePerGas：愿意为单位Gas支付的最高总费用

**生命周期**

```
创建和签名 - 广播 - 打包和验证 - 执行 - 最终确认
```

**交易对象**

- EOA

仅进行基础的账本更新，不需要运行EVM，Gas消耗为固定的`21000`Gas

- CA

解析Data后，启动EVM，执行代码后，生成日志

Gas的消耗为固定的21000Gas加上执行的Gas





## 智能合约

智能合约是部署在区块链上，由EVM自动运行的确定性可执行程序。本质就是一个合约账户（CA）

在EVM的执行环境中，分为三部分

```
代码区：存储合约编译后的EVM机器码
状态区：持久化保存状态变量
临时数据区：有栈和内存，保存临时数据
```

生命周期

```
高级代码(Solidity) - 编译 - 部署 - 调用执行
```

**运行机制与约束**

- 确定性

不允许产生任何随机或不确定行为

- 原子性与状态回滚

合约函数的执行是原子的，如果异常，交易引发的状态将被完全回滚

- Gas消耗

每条机器码都消耗特定的Gas

- 沙箱隔离

合约代码无权访问呢宿主机节点的内容
